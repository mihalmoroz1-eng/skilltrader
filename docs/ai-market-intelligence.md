# AI Market Intelligence

## Design input and adaptation

This stage uses architecture patterns from the user-provided `Shubhamsaboo/awesome-llm-apps` catalog snapshot (translated 16 November 2026), including DevPulse AI, Finance Agent Team, Trust-Gated Multi-Agent Research Team, LLM Panel, Mixture of Agents, Advisor Orchestrator Worker, Corrective RAG and typed Agentic RAG.

These are design references, not dependencies or copied applications. The implementation is native to the existing Skill Trader TypeScript/Node.js server and Zod/tRPC contracts. No Python agent framework is required for the production path.

- DevPulse AI: technical observations are separated from any future signal lifecycle.
- Finance Agent Team: specialist roles have narrow, different responsibilities.
- Trust-Gated Multi-Agent Research Team: inputs must pass deterministic quality checks before model calls.
- LLM Panel: a Critic performs a separate consistency pass over structured specialist outputs.
- Mixture of Agents / Advisor Orchestrator Worker: specialist results are produced independently and combined by a deterministic orchestrator.
- Corrective RAG and typed Agentic RAG: possible later research patterns; not part of this stage because no external news, web retrieval or RAG corpus is connected.

Reference repository: https://github.com/Shubhamsaboo/awesome-llm-apps

## Workflow

```text
Authenticated request
  -> per-user AI rate limit
  -> Binance Spot public candles
  -> deterministic OHLC validation and indicators
  -> Trust Gate
  -> Market Agent     ┐
  -> Strategy Agent   ├-> parallel structured outputs
  -> Risk Agent       ┘
  -> Zod schema + server evidence allow-list checks
  -> Critic Agent
  -> deterministic Orchestrator
  -> result + provenance + SHA-256 digest
```

The UI starts this workflow only when the user presses the analysis button. It is not run on the 30-second market-data refresh timer.

## Agent responsibilities

### Market Agent

Classifies a descriptive market regime and momentum from existing server-calculated indicators. It cannot calculate indicators, create price forecasts, recommend buying/selling, or issue LONG/SHORT labels.

### Strategy Context Agent

Classifies the type of technical context (trend, mean-reversion, mixed, unclear). It does not recommend a strategy, entry, stop, target, leverage or order.

### Risk Context Agent

Classifies technical volatility context using server-derived evidence. It does not calculate user-specific risk, position size, maximum loss, leverage or financial suitability. The deterministic Risk Engine remains the only authority for those functions.

### Critic Agent

Checks whether the three structured outputs are consistent with the same canonical facts and evidence allow-list. It returns only a verdict and fixed conflict codes. It is another model call, not an independent auditor or proof of correctness.

### Orchestrator

The orchestrator is deterministic code, not a fifth autonomous model. It accepts a result as `reviewable` only when the Critic returns `consistent` and no conflict codes. Otherwise the result is `inconclusive`. Neither state is a trading signal or a guarantee of predictive accuracy.

## Trust Gate

No AI agent is called unless all conditions pass:

- source is the approved Binance Spot public read-only adapter;
- market-data snapshot is no more than 30 seconds old;
- data-quality status is `ready`, with zero gaps;
- at least 50 consecutive closed candles are available;
- no more than one unclosed candle is present;
- indicator series aligns with the closed-candle series and the required latest indicator values are finite;
- the latest closed candle is not older than two fixed intervals for non-monthly intervals.

The latest forming candle is excluded from agent input. The agent context contains only the latest closed candle, the latest calculated indicators, the last eight closed candles, data-quality metadata and server-derived evidence codes.

The model may select only evidence codes generated by the server. Any code outside that allow-list causes the agent output to be rejected and the run to fail closed.

## Structured outputs and provenance

All four model calls use strict JSON Schema output, are validated again with Zod, have no available tools, have a 20-second timeout and disable automatic retry. The first three roles run in parallel; Critic runs after they all succeed. A partial agent result is not returned to the client.

Each completed result contains:
- a run ID;
- data source, symbol, interval, fetch/processing timestamps and closed-candle count;
- prompt version and model identifier per role;
- evidence and conflict codes;
- a SHA-256 digest over the canonical facts and structured outputs;
- explicit flags that no trade signal was generated and no order was executed.

The digest is a fingerprint for comparing returned evidence. It is not a persistent, tamper-evident audit log. Run history is not currently stored in a durable database table. Persistent append-only audit storage, retention policy and external hash anchoring are separate future work.

The current implementation uses the same configured model for each specialist call. Separate roles and prompts do not equal cross-provider model diversity or independent verification.

## Rate limits and operational constraints

- Two AI analysis starts per minute per user.
- Twenty AI analysis starts per UTC day per user.
- Maximum 10,000 tracked user keys in the process-local limiter.
- Four model calls per successful run (three parallel specialist calls plus Critic).
- No AI automatic retries.
- The limiter is process-local, not a distributed quota. Multi-instance production deployment requires a shared rate-limit service or gateway control.

The 0.5% / 2% ATR-to-price bands and 1.5% EMA20 extension test are coarse technical evidence categories for context only. They are not risk limits, stop distances, position-sizing rules or recommendations.

## Safety boundary

The result is descriptive market analysis only. It does not enter the existing synthetic demo scenario, Monte Carlo simulation, AI educational chat context, user risk profile or execution pipeline. No Binance account endpoints, credentials, paper orders or live orders are exposed to agents.

This stage does not implement live signal generation, signal approval, paper execution, news retrieval, external research, RAG, memory, persistent agent-run history, cross-provider review or autonomous tool use.
