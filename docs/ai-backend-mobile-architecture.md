# Архитектура мобильного AI-backend Skill Trader

**Статус:** проектирование, не реализация и не публикация. В текущем Android APK AI и сеть отключены; этот документ не разрешает deploy API, включение Database/Redis или платные model calls.

## Текущий серверный контракт

В приложении уже смонтирован Express/tRPC endpoint `/api/trpc`. `traderAssistant.chat` объявлен как `protectedProcedure`, валидирует данные схемой Zod, проверяет конфигурацию модели и лимитирует пользователя по сессии. `askTraderAssistant` последовательно выполняет три этапа: разбор намерения и выбор ID фактов → сверка ограниченного набора арифметики/рисков → выбор шаблонного объяснения или отказа. Сервер самостоятельно собирает финальный ответ; один вопрос может выполнить три model calls. Повторы после ошибок не автоматические. Это учебное объяснение синтетического сценария, не торговый совет, live-анализ или исполнение ордера.

Текущий клиент использует относительный URL `/api/trpc`, `credentials: include` и при наличии session token передаёт Bearer header. Relative URL подходит для веб-приложения, обслуживаемого тем же origin, но в Android WebView укажет на локальный Capacitor origin. Развёртывать сервер для решения этой проблемы не следует без отдельного разрешения.

## Предлагаемые online-компоненты

1. **Сборка.** Оставить существующий `android-demo` строго offline. В будущей online-сборке задать только публичную browser-safe константу `VITE_TRPC_API_URL=https://<approved-api-host>/api/trpc`; проверять HTTPS и пустое значение при сборке. Ключи модели, provider API credentials и долгоживущие application secrets туда не помещать.
2. **API.** Использовать существующий `/api/trpc` и процедуру `traderAssistant.chat`; не создавать альтернативный клиентский LLM endpoint. Сохранить `protectedProcedure`, Zod allow-list, ограничение только синтетическим контекстом и точный трёхэтапный pipeline. Сервер не должен принимать от клиента произвольную модель/URL/prompt и не должен выдавать intermediate JSON или chain-of-thought.
3. **Origin и CORS.** Включить CORS только после реального определения origin Android WebView. Capacitor обычно использует `https://localhost`; разрешать `capacitor://localhost` только если это подтверждается выбранной схемой в итоговой конфигурации. Возвращать allow-origin для точного origin, а не `*`; разрешить только необходимые методы и headers (включая `content-type` и `authorization`), отвечать на OPTIONS preflight. Для cookie с cross-origin credentials обязательны `Access-Control-Allow-Credentials: true`, точный origin и `SameSite=None; Secure`. Не включать wildcard origin вместе с credentials.
4. **Сессия.** До реализации выбрать и проверить одну Android-совместимую схему: OAuth authorization-code с PKCE через системный browser и краткоживущий access token, либо доказанный на устройстве защищённый cookie-flow. Предпочтителен PKCE; refresh token rotation и хранение — через Android Keystore/поддерживаемый Capacitor secure-storage plugin, не `localStorage`. Не переносить session из браузерного Preview и не добавлять bearer token в URL/logs. Текущий `startLogin`/Manus OAuth поток не объявлять совместимым с APK без device test.
5. **Сессии, лимиты и приватность.** Сейчас лимитер находится в памяти процесса и поэтому рассчитан на одиночный закрытый прототип. При нескольких backend instances rate limit перестаёт быть согласованным; до production нужен отдельно утверждённый распределённый механизм или platform gateway quota. Database и Redis сейчас выключены — не включать их в рамках офлайн APK. Не хранить переписки без явного решения; минимизировать логи вопроса и переданных данных, ограничить retention.
6. **Ошибки и UI.** Если сервер отсутствует, AI остаётся disabled с честным сообщением; без фиктивных ответов, скрытого retry или торговли. При 401/403 запрос не повторять вслепую: пройти явную авторизацию. На 429 и исчерпание credits отображать серверное понятное сообщение; не повторять платные этапы автоматически.

## Безопасные границы и критерий готовности

Online APK не считается готовым, пока отдельно не подтверждены: HTTPS endpoint и ownership, OAuth/PKCE на целевом Android, CORS/preflight для настоящего WebView origin, серверная авторизация и rate limiting, запрет прямых LLM-вызовов из клиента, стабильность трёх стадий без скрытых повторов, отсутствие сохранения/утечки пользовательского контекста и ручной синтетический smoke-test с заранее принятой стоимостью. Ни один из этих шагов не нужен для автономной демонстрации и ни один сейчас не выполнен.

**Не входит:** подключение реальных рыночных данных, персональный финансовый совет, инвестиционный сигнал, broker integration, ордера, автоматизация и публикация сайта/API.
