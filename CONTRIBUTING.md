# Участие в проекте

Спасибо за интерес к Skill Trader. Это учебный демонстрационный проект: графики и сценарии синтетические. Он не подключается к live-котировкам или брокеру, не отправляет ордера и не выдаёт персональных финансовых рекомендаций.

## Перед началом

Для работы нужны Node.js и pnpm `10.18.0` (версия pnpm закреплена в `package.json` и `pnpm-lock.yaml`). Установите зависимости:

```bash
pnpm install --frozen-lockfile
```

`pnpm dev` запускает приложение вместе с сервером. Полноценные server-side AI-вызовы зависят от авторизованной среды Manus и проектной конфигурации; не добавляйте ключи или токены в `.env`, исходный код, issue или pull request. Статический режим `pnpm dev:static` предназначен только для интерфейса и не включает AI endpoint.

Перед отправкой изменений запустите:

```bash
pnpm check
pnpm test
pnpm build
```

Тесты должны оставаться детерминированными и не должны обращаться к платной модели, внешним live-источникам или брокерам.

## Предлагаемые изменения

Откройте issue для крупного изменения или изменения границ продукта. Для небольших исправлений можно сразу создать ветку и pull request. В описании pull request укажите цель, поведение до и после, выполненные проверки и связанные issue. Для UI-изменений приложите снимки до/после для desktop и mobile, если они помогают понять результат.

Изменения должны сохранять учебные ограничения: только синтетические входные данные; без настоящих котировок, сигналов, брокерских действий, доступа к локальному журналу или скрытых модельных вызовов. Не ослабляйте валидацию server-side AI и allow-list тем. Новые вызовы модели требуют отдельного обоснования, явного пользовательского действия и тестов, не запускающих платный API.

Не включайте в коммиты секреты, реальные персональные/финансовые данные, build output, `node_modules` или файлы окружения. Используйте небольшие тематические коммиты и обновляйте README/TODO, когда меняются пользовательское поведение, ограничения или команды запуска.

## Pull request

Перед отправкой проверьте diff на случайно добавленные файлы и секреты. Убедитесь, что перечисленные выше команды завершились успешно, либо укажите, что именно не удалось проверить и почему. Поддерживайте уважительное обсуждение; запросы на изменение могут потребоваться для проверки безопасности, точности описания и сохранения учебного назначения проекта.
